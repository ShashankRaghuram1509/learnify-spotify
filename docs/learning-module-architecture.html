Overview & Scope

Learnify is a single-page web application (a Vite + React + TypeScript client) backed entirely by Supabase — PostgreSQL with Row-Level Security, JWT authentication, file storage, realtime subscriptions, and Deno-based Edge Functions. This document isolates and describes the Learning Module: everything a student touches while learning, and the AI chatbot that guides them with customized roadmaps and study help.

In scope — the learning module
  • AI Roadmap Chatbot — floating assistant giving personalized study roadmaps, course help & academic guidance
  • Course delivery — catalog, enrollment, video player, downloadable materials
  • Assessments — assignments & timed tests with browser-based proctoring
  • Progress & certification — progress tracking, completion, certificates
  • AI transcription — speech-to-text + summary of session recordings
Out of scope (referenced only where it gates learning)
  • Payments / Razorpay — appears only as the premium-enrollment gate
  • Placement & jobs (Adzuna, JSearch)
  • User-to-user chat & video-call scheduling
  • Admin platform analytics, MOU & partner management

AI Roadmap Chatbot — Deep Dive

The headline feature: a conversational assistant that produces customized learning roadmaps, study plans and course help. It is a thin, secure client that streams tokens from a large language model through an auth-gated Edge Function.

Client — AIAssistant.tsx
  • Global floating widget (bottom-right), mounted once in App.tsx across all routes
  • Requires an authenticated Supabase session before sending
  • POST to ${VITE_SUPABASE_URL}/functions/v1/ai-chat with Authorization: Bearer <access_token>
  • Reads a Server-Sent Events stream, parsing choices[0].delta.content and terminating on [DONE]
  • Renders the reply incrementally (token-by-token); handles 429 rate-limit & 402 usage-limit
Edge Function — supabase/functions/ai-chat
  • Decodes the JWT, extracts sub (user id); rejects unauthenticated calls with 401
  • Validates messages[]: 1–50 messages, each ≤ 4000 chars, role ∈ {user, assistant, system}
  • Prepends the educational system prompt (see below) that shapes the roadmap/guidance behaviour
  • Calls the LLM with stream: true and proxies the SSE stream straight back to the browser
  • Secret LOVABLE_API_KEY never leaves the server

Request & streaming data flow

User opens the widget and sends a message. The client appends it to local messages state.
AIAssistant retrieves the Supabase session and POSTs the full message history to the ai-chat function with the bearer token.
ai-chat authenticates (JWT sub) and validates the payload shape and limits.
ai-chat injects the system prompt and forwards [system, ...messages] to Lovable AI Gateway → google/gemini-2.5-flash, stream:true.
Gateway/model streams completion chunks (SSE) back to the function, which returns them as text/event-stream.
AIAssistant decodes each data: chunk and appends delta.content to the on-screen answer until [DONE].
System prompt (verbatim, in ai-chat/index.ts):
“You are a helpful educational AI assistant for a learning management system. You help students with their courses, answer questions about assignments, provide study tips, and assist with general academic guidance. Be encouraging, clear, and supportive.”
Design note — where the “customized roadmap” comes from. Roadmaps and study plans are produced dynamically by the LLM from the running conversation and the system prompt — they are generated per request and are not persisted to a dedicated roadmap table. The model receives the message history verbatim; there is currently no server-side injection of the student's enrolled-course or progress data into the prompt (a natural extension point — see §10).

Discover & Enroll

Courses & CourseDetail browse the courses table (with modules). Enrolling calls the create-enrollment Edge Function, which enforces access rules server-side:

  • Free courses → enroll immediately
  • Premium courses → allowed if profiles.subscription_tier ∈ {Lite, Premium, Premium Pro} and unexpired, or a completed payments row exists for the course
  • Insert into enrollments is done with the service role, bypassing RLS after checks pass

Learn — CourseViewer.tsx

  • Verifies enrollment & (for premium) payment/subscription before revealing content
  • Embeds the lesson video via a normalized YouTube embed URL
  • MaterialsList lists course_resources (pdf/video/link) ordered by position
  • Shows enrollment progress and a CourseReview
  • Optional TranscriptViewer renders AI transcript + summary from transcripts

Assess — AssignmentsList · TakeTest

  • Assignments & “tests” share the assignments table (distinguished by type)
  • Starting a test inserts an assignment_submissions row (status pending) and starts a countdown from duration_minutes
  • Supports free-text answers or an embedded Google Form (attachment_url)
  • Auto-submits at time-up; results tracked in student_test_attempts
  • Progress can be boosted via enrollments.test_progress_bonus

Track & Certify

  • ProgressTracker / EnrolledCoursesList compute % from progress + test_progress_bonus (capped 100)
  • video_watch_tracking records minutes watched & last position
  • CertificateManager surfaces the student's certificates (joined to course titles)

Assessment & Proctoring Subsystem

Timed tests are monitored client-side by the useProctoring hook, with every event persisted for teacher review.

Monitored events → proctoring_logs

tab switch (visibilitychange)window blur copypaste right-click (contextmenu)fullscreen exit

Fullscreen is requested on start; each violation increments a live counter shown to the student.

Enforcement → proctoring_violations
  • Aggregates violation_count and failed_attempts per (assignment, student)
  • blocked_until can lock a student out after repeated violations
  • Enabled per-assignment via assignments.proctoring_enabled

09

Authentication & Access Control

Auth — useAuth.tsx
  • React context wrapping Supabase Auth; subscribes to onAuthStateChange + getSession()
  • Exposes user, session, userRole, subscriptionTier, subscriptionExpiresAt and signIn/signUp/signOut
  • New users default to the student role via a DB handle_new_user trigger
Roles & subscription
  • Roles read from user_roles; effective role by priority admin › teacher › student
  • Subscription tier/expiry read from profiles; premium checks enforced in Edge Functions, not just the client
  • Routes protected by ProtectedRoute (allowed-roles); data protected by Postgres RLS + has_role()
10

Security Posture & Extension Points

Strengths
  • All AI / third-party secrets held server-side in Edge Functions; never shipped to the browser
  • Chatbot input validated (count, length, roles) before reaching the model
  • Premium access re-checked server-side; privileged writes use the service role only after authorization
  • Row-Level Security + has_role() as the data-access backbone
Opportunities (roadmap)
  • Context-aware roadmaps — inject the student's enrolled courses & progress into the chatbot system prompt
  • Persist roadmaps — store generated study plans (e.g. a roadmaps table) for resume/track
  • Rate-limit ai-chat per user; verify JWT signature (not just decode) at the edge
  • Wire chat replies to render markdown; add conversation history persistence

Summary. The learning module is a cleanly layered slice: a React client for discovery, learning, assessment and certification; an always-on AI chatbot for customized roadmaps and guidance; and a Supabase backend where Edge Functions broker every privileged action and every AI call (Gemini 2.5 Flash for chat, Groq Whisper + Llama 3.3 for transcription), with Postgres RLS and role-based access as the security backbone.
